## ADR-0001 · 同源嵌入采用「路径命名空间合并」，不做子路径反代

**状态**：已采纳（M1）

### 背景

需求是"重新设计 ComfyUI 界面，不是照搬网页端"。M1 拍板走"外壳自研 + 画布同源嵌入 + 主题注入"。
最初设想的实现是：启动器反代把 ComfyUI 挂在 `/comfy/` 子路径下，前端用 iframe 加载 `/comfy/`。

### 查证结果（2026-11，ComfyUI master）

| 事实 | 来源 | 影响 |
|---|---|---|
| aiohttp 路由全部注册在根路径：`/ws`、`/view`、`/upload/image`、`/object_info`、`/api/jobs` | `server.py` 路由注册段 | 后端没有 basePath 概念，无法整体挂到前缀下 |
| 静态资源用 `web.static('/', self.web_root)` | `server.py:1390` | 静态服务也吃根路径 |
| 前端构建 `base: DISTRIBUTION === 'cloud' ? '/' : ''` | `ComfyUI_frontend/vite.config.mts` | HTML 里的资源引用是**相对**的 |
| 但运行时 API 调用是**绝对根路径**（`fetch('/object_info')` 之类） | 前端源码 | 相对资源能搬，绝对 API 不能搬 |

**结论：子路径反代必然 404。** 因为页面可以放在 `/comfy/`，它发出的 `/object_info` 却会打到启动器自己的命名空间。

### 决策

放弃子路径反代，改用**路径命名空间合并**：

- 启动器前端与 ComfyUI 前端**同源、同端口**，只是路径前缀不同
  - 启动器：`/`、`/assets/*`、`/api/*`（Olivia 自己的）
  - ComfyUI：`/comfy/*` → 反代到 `127.0.0.1:<实例端口>`，且**改写 HTML 里的相对资源为 `/comfy/...`**
- 前端用 iframe 加载 `/comfy/`，`postMessage` 做双向通信
- 因为同源，`/ws` 可以直接由启动器进程持有并复用，不需要跨域 WebSocket

### 代价

1. **需要改写 ComfyUI 的 `index.html`**：把相对路径注入成 `/comfy/` 前缀。这是唯一可靠的做法，且必须跟随上游前端构建方式变化。风险等级：中。对策：启动器持有自己构建的 index.html 模板，不依赖上游 HTML 结构细节。
2. **`/api/*` 命名空间冲突**：ComfyUI 也有 `/api/*`。命名空间合并时，启动器的 `/api/*` 必须优先匹配，ComfyUI 的一律走 `/comfy/api/*`。这条要写进路由白名单，并加集成测试。
3. **Cookie / localStorage 同源共享**：ComfyUI 的 `user/` 设置与启动器设置会共用 localStorage 命名空间。必须给启动器所有 key 加 `olivia.` 前缀，并在注入脚本里隔离。

### 备选方案与被否原因

| 方案 | 否因 |
|---|---|
| 子路径反代 | 见上，API 绝对路径必然 404 |
| 独立端口 + 跨域 iframe | 跨域无法注入主题、无法读 DOM、WebSocket 需额外鉴权，体验断裂 |
| 直接改 ComfyUI 源码加 basePath | 违反"不修改 ComfyUI 源码"原则，且上游升级即失效 |
| 完全自研画布 | M1 范围失控（见 ADR-0002） |

### 验证要求

M1 验收必须包含：在 `/comfy/` 下加载画布，跑通一条完整工作流（含图片预览 `/view`、队列 `/queue`、WebSocket 进度），且启动器自身 `/api/*` 未被污染。

## ADR-0002 · 画布不自研，M1 只做外壳

**状态**：已采纳（M1），M2 重新评估

### 背景

"重新设计 GUI"如果理解为重写节点编辑器，工作量是十万行级：节点渲染、连线命中测试、撤销栈、子图、虚拟化、扩展 API、快捷键系统。

### 决策

分三层：

| 层 | M1 | M1.5 | M2 |
|---|---|---|---|
| 启动器外壳（实例/队列/硬件/资产/模型/设置） | 100% 自研 | — | — |
| 画布 | 同源嵌入 + 主题注入 | 注入增强（快捷键、拖拽、中文化、显存预估） | 自研编辑器，只覆盖高频 20% 节点 |
| 复杂工作流 | 嵌入画布 | 嵌入画布 | 双模式并存 |

**用户感知目标**：看起来是一个客户端，而不是"网页套壳"。达成手段是外壳完全自研 + 画布主题深度统一（配色、字体、圆角、线宽全部换成橄榄纸感），而不是重写编辑器。

### 代价

画布的深层交互（右键菜单、节点库、设置面板）仍然是 ComfyUI 原生的，只能靠 CSS 与注入脚本改造。上游前端大改版时，注入脚本可能失效。对策：注入脚本做特性检测，失效时降级为原生外观而不是白屏。

## ADR-0003 · 核心逻辑用 Python，Rust 只做壳

**状态**：已采纳

### 决策

- `services/core`：Python 3.12 + FastAPI，负责部署引擎、进程守护、NVML 采集、资产索引
- `apps/desktop`：Tauri 2（Rust），只负责窗口、托盘、单实例、原生文件对话框、自动更新

### 理由

ComfyUI 是 Python 项目，环境事故的 90% 发生在 pip / torch / CUDA 层。用 Python 写核心可以直接 `import torch` 做自检、复用 `venv` 与 `importlib.metadata`、在启动前跑真实探针。用 Rust 重写这些只会把问题变成 FFI 问题，且无法复用生态。

### 代价

安装包需要捆绑一个 Python 运行时（或用 uv 按需下载）。体积从纯 Rust 的 ~10 MB 增加到 ~35–45 MB（含运行时压缩）。接受：目标用户装的是 CUDA 与模型，几十 MB 不是瓶颈。

## ADR-0004 · 前端只走本机 HTTP，不走 Tauri IPC

**状态**：已采纳

### 决策

前端所有业务调用走 `http://127.0.0.1:<port>` + WebSocket。前端代码中**不允许**出现 `@tauri-apps/api` 的业务调用（窗口控制除外）。

### 理由

这是"先做 Web 再转桌面"能成立的前提。浏览器里 `pnpm dev` 就是完整 Web 版；打包只是换壳，不需要维护两套代码路径。

### 代价与强制措施

本地开 HTTP 端口是有风险的，必须同时满足：

1. 只绑 `127.0.0.1`，绝不绑 `0.0.0.0`
2. 每次启动生成一次性 token，通过 `window.__OLIVIA_BOOT__` 注入前端
3. 校验 `Origin` 与 `Sec-Fetch-Site`，拒绝非本机来源
4. 端口随机，写回 `instance.json`

缺任何一条，局域网内任意网页都能通过 CSRF 驱动启动器（例如静默删除实例、改写产物目录）。

## ADR-0005 · 许可证 GPL-3.0

**状态**：已采纳

### 理由

本项目分发/调用 ComfyUI（GPL-3.0）。选择 GPL-3.0 是最省心的合规路径，也符合开源社区预期。

### 代价

- 不能把启动器闭源分发
- 若未来要接入闭源商业模块（如付费云渲染 SDK），必须做进程隔离而非链接，并单独评估
- 赞助商不能要求功能独占或闭源分支

## ADR-0006 · M1 只做 Windows

**状态**：已采纳

### 决策

M1 只支持 Windows 10 1809+ / 11，x64。macOS 与 Linux 推迟到 M2 评估。

### 理由

Windows 占 ComfyUI 用户绝大多数，且环境问题最集中（CUDA、路径、杀软、控制台编码）。把 Windows 做到"零终端"已经足够形成口碑。

### 代价

- 技术选型上仍保持跨平台可能：不写 Windows-only 的 Python 逻辑，路径处理统一走 `pathlib`
- macOS 需要额外处理 MPS、公证签名、Gatekeeper，Linux 需要处理发行版差异与 AppImage/Flatpak，均为独立工作量
- **明确不在 M1 承诺**，避免用户预期落空

## ADR-0007 · 硬件归因必须标注口径

**状态**：已采纳

### 背景

需求是"实时查看每条工作流的 GPU 占用情况"。但 NVML 只提供**整卡**指标，无法按进程或按工作流拆分。

### 决策

M1 采用**时间窗口归因**：订阅 ComfyUI `/ws` 的 `execution_start` → `executing` → `execution_success`，把该区间的 NVML 采样归到对应 `prompt_id`。

UI 必须同时显示：峰值显存、平均利用率、峰值温度、耗时、每节点耗时，并**显式标注**：

> 峰值为该时间窗口内的整卡采样，含模型常驻与上下文开销，不等于该工作流独占用量。

### 理由

不标口径会被当成"精确计量"，一旦用户发现两条串行工作流的显存读数不独立，信任直接崩塌。宁可说清楚边界，也不要做漂亮但错误的数字。

### 后续

M1.5 提供"进程隔离模式"：每工作流独立 ComfyUI 进程，PID ↔ 显存可精确对应。代价是冷启动 +8~15 s，默认关闭。

## ADR-0008 · 资产目录强制指定，不做默认值

**状态**：已采纳

### 决策

用户未指定资产存放位置时：

- 总览页常驻警示条
- 资产页整页空态，文案写明后果
- 主按钮直达文件夹选择器
- **禁止**静默写入某个默认路径

### 理由

需求明确要求"必须要让用户指定工作流产物存放位置"。静默兜底会导致用户在重装/迁移后找不到几个月的心血产物，这是最伤用户信任的一类 bug。

### 实现约束

ComfyUI 的 `--output-directory` 只影响新产物，历史产物仍在实例目录。切换目录时必须询问"是否迁移历史产物"，并提供迁移进度与失败回滚。

## ADR-0009 · 无签名证书期间做手动更新，不做「半自动」更新

**状态**：已采纳（M1 / M1.5）

### 背景

PLAN 的 M1.5 承诺"打包与自动更新"。但 Tauri updater 在 Windows 上**强制 minisign 签名校验**，没有代码签名证书这条路是死的；而 OV/EV 证书年费数千元且 EV 需要企业实体，个人开源项目初期无法承担。

### 决策

在取得签名证书之前，更新流程为**手动式**：

1. 启动器检查 GitHub Releases（走镜像）比对版本号
2. 下载后客户端计算 SHA256，与 Release 页公布值比对，不一致即拒绝
3. 用户手动运行安装包完成更新

Tauri updater 在证书到位后启用，作为独立 PR。

### 理由

不校验哈希的自动更新等于把供应链攻击面交给镜像与网络路径；而在无签名的前提下做"看起来自动"的更新，只会制造虚假安全感。明确的手动流程 + 显式哈希校验是当前约束下最诚实的方案。

### 代价

- 更新体验断裂：用户要多点一次安装包
- 未签名安装包会被 SmartScreen / 杀软拦截：README 公布 SHA256，FAQ 提供核对与放行指引
- 这类拦截是 Windows 启动器分发的头号流失点，必须前置写进文档，而不是等用户来问

### 备选方案与被否原因

| 方案 | 否因 |
|---|---|
| 自签证书 + updater | 不被系统信任，SmartScreen 照拦，还引入证书分发问题 |
| 关闭 updater 签名校验 | 直接制造供应链攻击面，不可接受 |
| 等证书到位再做整个 M1.5 | 打包与分发验证不应被证书阻塞；手动流程先行能提前暴露分发问题 |

## ADR-0010 · M1.5 之前的发行形态：绿色源码包，Core 同源服务前端

**状态**：已采纳（M1.1a 起，M1.5 重审）

### 背景

M1.5 的正式形态是 Tauri 安装包（捆绑 Python 运行时，约 35–45 MB）。但在 Tauri 壳落地之前就需要对外提供可运行版本：分发验证、真实用户反馈、以及 ADR-0009 手动更新流程的预演，都不应被壳的开发进度阻塞。

### 决策

alpha 阶段发行**绿色源码包**（zip，约 120 KB）：

1. 内容：`olivia_core` 源码 + `requirements.txt` + 前端构建产物 + `Olivia.bat` 引导脚本 + LICENSE + 中文说明
2. 运行方式：`Olivia.bat` 检测 Python 3.12+，首次运行自建 venv 并安装依赖（默认源失败自动切清华镜像），随后 `python -m olivia_core --serve-web web`
3. **Core 同源服务前端**：构建产物由 Core 挂在 `/`，浏览器访问 `http://127.0.0.1:<端口>` 即完整界面。一次性令牌由 Core 写入同源 HTML 的 `window.__OLIVIA_BOOT__`——与 ADR-0004 规定的注入路径**同一条**，将来 Tauri 壳只是换成壳来注入，前端零改动
4. 引导脚本全 ASCII：cmd 在 chcp 65001 下会把多字节行错位拆行；中文文案由随包说明与 Web 界面承担
5. 每次发布附 `SHA256SUMS.txt`，公钥仓库 README 公布摘要值（ADR-0009 流程预演）

### 理由

- 能读到 `__OLIVIA_BOOT__` 令牌的客户端，本就处于「可读数据根 core.json」的同一信任边界（都在本机、同源）；API 侧 Origin / Sec-Fetch-Site / 令牌校验不因此放松
- 端口被占时 Core 自动从 8600 起向后探测，写入 core.json，引导脚本与用户无需硬编码端口
- 源码包 + 系统已有 Python 对目标用户（ComfyUI 用户人手一份 Python）几乎零成本，且完全规避了无签名 exe 的分发信任问题——这个形态下根本没有 exe

### 代价

- 首次运行要联网装依赖（约 1–2 分钟），体验弱于安装包；镜像兜底缓解
- 依赖用户的 Python 环境；3.12 以下版本会被引导脚本明确拒绝并给出安装指引
- 引导脚本是 cmd 批处理，无进度条、错误提示简陋；M1.5 换 Tauri 后整段废弃
- 「绿色版」没有卸载器：删除目录 + 删除数据根 `%LOCALAPPDATA%\OliviaComfyUI` 即干净，需写进随包说明

### 备选方案与被否原因

| 方案 | 否因 |
|---|---|
| 等 Tauri 壳完成再发行 | 分发验证与用户反馈被壳进度阻塞；ADR-0009 已拍板手动流程先行 |
| 发行 exe 安装包（pyinstaller 等） | 无签名 exe 被 SmartScreen 拦截是头号流失点（ADR-0009），alpha 阶段不值当引入第二套打包链 |
| 前端由独立静态服务器服务 | 多一个进程、多一个端口，还须跨域解决令牌与 CORS；同源服务是零成本方案 |
